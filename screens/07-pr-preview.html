Fix: Parser fails when handling nested template tags

Resolves Issue #841.

Root Cause Analysis

The recursive descent parser in src/parser/html.ts was incorrectly maintaining state when encountering deeply nested custom template tags. Specifically, the token stack was not being popped correctly upon encountering closing tags that matched an ambiguous pattern regex, leading to a stack overflow or malformed AST.

Changes Proposed

  • Updated parseNode() to strictly validate closing tag boundaries against the current context depth.
  • Introduced a dedicated TemplateTagState interface to replace the loose tuple structure.
  • Added boundary checks in the tokenizer to prevent runaway lookaheads on invalid HTML.
